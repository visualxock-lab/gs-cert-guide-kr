1 입력

사용자설명서·매뉴얼·기능정의서·메뉴 테이블을 넣으면 제목 구조를 읽어 화면 단위 기능 후보를 만듭니다. 파일은 브라우저 안에서만 처리되고 어디로도 전송되지 않습니다. 설명서가 없으면 설명서가 없을 때 탭을 보세요.

정적 추출 · LLM 0회
.txt · .md · .csv · .tsv · .xlsx · .docx · .pdf · .json 파일을 여기로 끌어놓거나 눌러서 선택하세요 (여러 개 가능)

docx·pdf는 인터넷에서 변환 라이브러리(CDN)를 한 번 받아옵니다. 사내망에서 막히면 텍스트 붙여넣기를 쓰세요. 한글(.hwp/.hwpx)은 PDF로 저장해서 넣거나, 2번의 2-B 원문 파일을 LLM에 직접을 쓰세요.

형식별로 무엇을 읽나요?
  • .txt / .md — # 제목, 1.·1.1·1-1·제1장·가.·(1) 번호, - □ ○ ▶ 글머리표, 들여쓰기로 계층을 만듭니다. "~합니다"로 끝나는 절차문·설명문과 목차의 점선·쪽번호는 걸러 냅니다.
  • .csv / .tsv / .xlsx — 기능표(대분류·중분류·기능명·RISK 영역 등)는 그대로, 메뉴 테이블(메뉴ID·상위메뉴ID·메뉴명·사용여부)은 상하위 관계로 트리를 만들어 읽습니다. EUC-KR(엑셀 기본 저장)도 읽습니다.
  • .docx — 제목 스타일과 목록 구조를 살려 읽습니다. 문서 안에 기능표가 있으면 그 표를 우선합니다.
  • .pdf — 텍스트 줄과 들여쓰기를 읽고 쪽 번호를 근거로 붙입니다. 매 쪽 반복되는 머리글·바닥글은 뺍니다. 스캔 이미지 PDF는 읽지 못합니다(이때는 2번의 2-B 원문 파일을 LLM에 직접).
  • .json — 공통 JSON(product-profile)을 불러와 기능목록을 병합합니다.

예시는 모두 가상값입니다(○○ 스마트 설비관리 시스템 V1.0). 실제 문서를 넣을 때 고객사명·계정·IP는 마스킹을 권합니다.

설명서가 아예 없을 때 쓰는 방법입니다. 설명서가 있으면(스캔 PDF·한글 파일 포함) 파일 업로드에 넣고 2번에서 다음 단계를 고르세요. 아래 프롬프트들은 모두 같은 기능 단위 규칙과 같은 JSON 형식을 쓰고, LLM이 준 결과는 2번의 2-C LLM 결과 붙여넣기에 넣습니다. LLM 사용료는 업체 본인 계정에서만 나갑니다.

메뉴 테이블 내보내기 가장 정확LLM 불필요

웹 시스템은 메뉴를 DB 테이블(메뉴ID·상위메뉴ID·메뉴명·사용여부·정렬순서)에 두는 경우가 많습니다. 관리자 화면의 메뉴 관리에 엑셀 내보내기가 있으면 그걸로 충분하고, 없으면 테이블을 CSV로 내보내 파일 업로드에 넣으세요. 상하위 관계로 트리를 만들고, 사용여부가 N인 메뉴는 뺍니다.

소스 저장소 → 코딩 에이전트 개발자용

  1. Claude Code·Cursor·Codex 같은 도구로 제품 저장소를 엽니다.
  2. 프롬프트를 붙여넣으면 라우트·메뉴 설정·화면 컴포넌트를 찾아 feature-list.json을 만듭니다.
  3. 그 JSON을 2번 2-C에 붙여넣거나 공통 JSON 불러오기로 넣습니다.

화면 캡처 → 내 ChatGPT·Claude 설치형·모바일·장비 탑재형

  1. 메뉴를 하나씩 열어 화면을 캡처합니다(사이드바·탭이 보이게).
  2. 캡처를 LLM 대화창에 첨부하고 프롬프트를 붙여넣습니다.
  3. 나온 JSON을 2번 2-C에 붙여넣습니다.

프롬프트에는 3번의 제품 정보(제품명·버전·배포 형태)가 들어갑니다. 먼저 채우고 복사하면 결과가 더 정확합니다.

또는 아래에 JSON을 붙여넣으세요.

불러오면 제품 정보·구성요소는 유지하고, 기능목록은 현재 표에 병합합니다(같은 대·중·기능명은 하나로 합치고 세부 동작을 합칩니다). 예전 4단계(소분류 포함) 형식도 3단계로 바꿔 읽습니다.

  6. 핵심은 제품이 존재하는 이유인 주된 처리 화면에만 표시합니다(보통 전체의 15~25%). 업무와 관련 있어도 설정·기준정보 관리·통계 조회·공통 기능은 빼세요. 최종 RISK 영역은 인증기관이 정합니다.

비공식 도구 인증 적합·범위를 판정하지 않습니다 · 입력한 자료는 브라우저 밖으로 전송되지 않습니다

이 도구가 하지 않는 것

  1. 인증 적합·부적합을 판정하지 않습니다. 출력은 언제나 “초안/후보”입니다.
  2. 인증 범위를 단정하지 않습니다. 범위 판단은 인증기관 확인 사항입니다.
  3. 공식 기준을 대체하지 않습니다. 고시·기관 안내·교부된 체크리스트가 우선입니다.
  4. 업체 자료를 수집·전송하지 않습니다. 모든 처리는 브라우저 안에서만 이루어집니다.
  5. 실제 값 노출에 주의하세요. 예시는 가상값이며, IP·계정·고객사명은 마스킹 후 사용하길 권합니다.
