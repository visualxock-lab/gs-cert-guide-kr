## 이 문서의 위치 — "초안"과 "정식 체크리스트"의 구분

GS인증 준비에서 **가장 먼저 멈춰야 하는 손실**은 인증 범위(제품명·버전·기능 목록)를 확정하지 않은 채 제품설명서·사용자취급설명서·화면 캡처부터 쓰는 것입니다. 범위가 중간에 바뀌면 문서 3종과 캡처를 처음부터 다시 맞춰야 합니다.

한 가지 먼저 구분할 점이 있습니다.

## 1. 견적 문의 전에 정리할 5가지

견적의뢰서와 사전상담을 넣기 전에 아래 5가지를 한 장에 적어 두면, 견적 산정과 일정 협의가 훨씬 빨라집니다.

| # | 정리할 항목 | 왜 필요한가 | 적는 요령 (예시) |
| --- | --- | --- | --- |
| **1** | **제품명 · 버전** | 인증서·성적서에 찍히는 공식 문자열이자 모든 문서의 기준점 | `OO 스마트 관제 플랫폼 V1.0` (대소문자·공백 통일) |
| **2** | **배포 형태 · 구성요소** | 시험환경 구성과 시험 공수 산정의 기준 | 웹 SaaS / 온프레미스 서버 + 웹 클라이언트 / 모바일 앱 + API 서버 등 |
| **3** | **기능 범위 · 기능 수** | 시험 범위와 수수료 산정의 핵심 입력 | 대분류·중분류·기능명 기준 **총 N개 화면(기능)**, 핵심 기능 표시 |
| **4** | **운영·시험 환경** | 지원 OS·브라우저·DBMS·외부 연계 여부 확인 | Linux(Ubuntu 22.04) · PostgreSQL 15 · Chrome/Edge · 외부 API 1종 |
| **5** | **수수료 감면 · 면제 증빙** | 해당 시 수수료 할인 또는 보안성 평가 면제 적용 | 중소기업확인서, 관련 협회 회원 증빙, 보안성 평가 면제 대상 증빙 |

### 자주 빠지는 실수 3가지

1. **인증 범위 밖 기능이 화면에 남아 있음**: 베타 메뉴, 관리자 전용 디버그 화면, 미완성 탭이 제품에 그대로 보이면 "설명서에 없는 기능이 구현되어 있다"는 보완 사유가 됩니다. 범위 밖 기능은 빌드에서 빼거나 권한·플래그로 메뉴와 직접 URL 접근을 모두 막아야 합니다.
2. **외부 연계·하드웨어 의존성을 빼고 문의함**: 외부 API, AI 모델, CCTV·센서 장비 연계가 시험 대상 흐름에 포함된다면 견적 단계부터 함께 알려야 시험환경 구성이 어긋나지 않습니다.
3. **제품 설명서에 "좋은 말"만 있고 기능 단위가 없음**: "실시간 모니터링을 제공한다"가 아니라, 실제로 평가자가 들어가서 눌러 볼 **화면 단위**로 쪼개야 기능 수가 나옵니다.

## 2. 기능목록(대·중·소) 초안 뽑기 — "화면 1개 = 기능 1개"

실무에서 기능목록 초안을 잡을 때 가장 헷갈리는 부분은 **"어디까지를 1개 기능으로 셀 것인가"** 입니다. 아래 4가지 규칙으로 정리하면 이후 체크리스트 작성과 문서 목차 구성까지 그대로 이어집니다.

### 기본 원칙 4가지

1. **3단계 계층으로 정리합니다**: `대분류` (최상위 메뉴 또는 모듈/SW명) → `중분류` (상위 메뉴) → `기능명` (실제 화면·탭 단위).
2. **화면 1개 = 기능 1개**: 한 화면 안의 등록·수정·삭제·검색·엑셀 내보내기 버튼, 같은 화면 안의 결과 목록 패널, 그 화면에서 열리는 단순 팝업·모달은 별도 기능으로 쪼개지 않고 **세부 동작** 괄호 안에 묶습니다.
   - 예) `사용자 관리 (등록, 수정, 삭제, 검색)` → **기능 1개**
3. **별도 화면·독립 탭이면 나눕니다**: 메뉴가 다르거나, 독립된 URL/화면 전환으로 완전히 다른 업무를 처리하면 별도 기능으로 분리합니다.
4. **로그인·공통 오류·로그아웃** 등 기본 공통 화면도 시험 대상에 포함되므로 누락하지 않습니다.

### 예시 (일반화된 가상 예시)

| 기능 ID | 대분류 | 중분류 | 기능명 (세부 동작) | 핵심 기능 | 근거 위치 |
| --- | --- | --- | --- | --- | --- |
| F-001 | 공통 | 인증 | 로그인 (아이디/비밀번호 입력, 비밀번호 초기화) | Y | 매뉴얼 §2.1 |
| F-002 | 대시보드 | 현황 요약 | 통합 현황 조회 (기간 필터, 차트 조회) | Y | 매뉴얼 §3.1 |
| F-003 | 시스템 관리 | 계정 관리 | 사용자 관리 (사용자 등록, 수정, 비활성화, 검색) | - | 매뉴얼 §5.1 |
| F-004 | 시스템 관리 | 이력 관리 | 감사 로그 조회 (기간·사용자별 조회, CSV 내보내기) | - | 매뉴얼 §5.3 |

## 3. 짝꿍 도구: 기능목록 추출기 (`tools/feature-list-extractor.html`)

위 규칙대로 매뉴얼이나 메뉴표에서 기능목록 초안을 바로 뽑아 엑셀로 내려받을 수 있는 브라우저 도구입니다. **서버 전송이나 API 호출 없이 100% 브라우저 내부에서만 동작**하므로, 사내 매뉴얼이나 메뉴표를 올려도 외부로 나가지 않습니다.

### 지원 입력 경로

| 상황 | 입력 방법 | 처리 방식 |
| --- | --- | --- |
| **설명서·매뉴얼이 있는 경우** | `.docx`, `.pdf`, `.txt`, `.md` 파일 업로드 또는 텍스트 붙여넣기 | 브라우저 정적 추출도 가능하지만, **"프롬프트 복사"로 본인 LLM(ChatGPT·Claude 등)에서 JSON을 뽑아 붙여넣는 쪽이 정확도가 훨씬 높습니다** |
| **기존 기능표·DB 메뉴표가 있는 경우** | `.csv`, `.tsv`, `.xlsx` 업로드 | 기능표는 그대로 읽고, DB 메뉴 테이블(`메뉴ID`, `상위메뉴ID`, `메뉴명`, `사용여부`)은 상하위 트리 변환(미사용 메뉴 제외) |
| **설명서가 아직 없는 경우** | 소스 코드 / 화면 캡처용 **전용 프롬프트 복사** | 독자 본인의 ChatGPT·Claude·Cursor에서 JSON을 뽑아 도구에 붙여넣기 |
| **1편 구성도 빌더를 이미 쓴 경우** | **공통 JSON(`product-profile`) 불러오기** | 1편 `diagram-builder.html`에서 만든 JSON의 제품명·버전·구성요소를 그대로 이어받아 병합 |

### 출력 형식

- **엑셀 (`.xlsx`)**: 기능목록 시트(기능 ID·대분류·중분류·기능명·RISK 영역·핵심기능·근거) + 요약 시트(제품명·버전·배포형태·건수)
- **CSV (`UTF-8 BOM`)** / **마크다운 표**
- **공통 JSON (`product-profile`)**: 이후 5·6·7·9·11회차 도구에서 그대로 이어서 재사용

> **실무 팁 — 가장 정확한 방법**: 브라우저 정적 추출은 목차 구조를 빠르게 훑는 데 좋고, 실제 제출용 초안에 가깝게 뽑으려면 **도구 안의 「프롬프트 복사」 버튼으로 본인 LLM(ChatGPT·Claude·Cursor 등)에 설명서·소스·캡처를 넣어 JSON을 만든 뒤 붙여넣는 편이 정확도가 가장 높습니다.** 「화면 1개 = 기능 1개」 단위 묶기와 세부 동작 분류를 문맥에 맞게 훨씬 깔끔하게 처리해 줍니다.

> **도구가 하지 않는 것**: 이 도구는 인증 적합·부적합을 판정하거나 인증 범위를 단정하지 않습니다. 출력물은 항상 검토용 초안이며, 실제 인증 범위와 체크리스트는 인증기관 확인이 우선합니다.
