# GS인증 사전준비 자가진단 체크리스트

> **1회차 · 실무 가이드.** 접수 전에 스스로 점검하는 체크리스트와, 반복해서 지적되는 결함 5가지를 Before/After로 정리했습니다.
> 이 체크리스트는 과학기술정보통신부 고시 「소프트웨어 품질인증 운영에 관한 지침」 제10~12조(제품설명서·사용자취급설명서·실행 소프트웨어 품질인증 기준)와 ISO/IEC 25023(제품 품질 측정), ISO/IEC 25024(데이터 품질 측정)의 관점을 실무 순서로 재배열한 것입니다.

## 사용법

- **접수 전**: 0~2장을 먼저 봅니다. 여기서 답이 안 나오는 항목이 곧 견적·일정 산정의 변수입니다.
- **문서 작성 중**: 1~2장을 문서 목차 삼아 씁니다. 항목마다 근거 조항을 적어 두었으니, 문서에 대응 절이 있는지 확인합니다.
- **시험 전날**: 3~4장만 다시 봅니다. 환경·계정·데이터는 이 단계에서 고칠 수 있는 마지막 지점입니다.
- 체크 표시가 안 되는 항목은 **"아직 모른다"**는 뜻입니다. 모르는 채로 접수하면 그 항목이 1차 보완으로 돌아옵니다.

## 0. 인증 범위와 신청 정보

- [ ] 제품명과 버전이 **인증서에 찍힐 문자열 그대로** 확정되었다 (화면 표기·문서 표기·파일명이 동일)
- [ ] 인증 등급(1등급 / 2등급)을 정했다 — 2등급은 업무적합성 기술서가 추가로 필요하다(§9, §13①3)
- [ ] 인증 범위에 포함할 **기능 목록**이 확정되었다 (모듈 단위로 번호를 붙여 관리)
- [ ] 인증 범위에서 **제외할 기능**을 정하고, 제품에서 어떻게 감출지(권한·플래그·별도 배포) 정했다
- [ ] 제품이 인증 대상인지 확인했다 — 단순기능 SW, 독자 환경 전용, 사행성, 위해성 SW는 대상 제외(§8①)
- [ ] 이전에 인증받은 제품이라면 재인증(주요변경/부분변경) 해당 여부를 판단했다
- [ ] 배포 형태(온프레미스 설치형 / 클라우드 SaaS / 장비 탑재형 / 스토어 배포 앱)를 문서에 명시했다
- [ ] 다국어 지원 시험(영문 성적서) 신청 여부를 정했다 — 신청 시 외국어 문서를 함께 준비해야 한다
- [ ] 신청 담당자·기술 담당자·연락처를 정리했다(시험 기간 중 연락 가능한 번호 포함)
- [ ] 중소기업확인서·협회 회원 증빙 등 **수수료 할인 서류**를 챙겼다
- [ ] 정보보호 사전인증(CC인증 등)이 있어 보안성 평가 면제 대상인지 확인했다 — 해당 시 증빙 사본 필요(§12⑨)

## 1. 제품설명서 (고시 §10)

- [ ] 표지에 소프트웨어 **명칭·버전**이 있다 (§10②1)
- [ ] 공급자명·주소·웹사이트가 있다 (§10②2)
- [ ] 운영 지원 여부와 지원 범위가 적혀 있다 (§10②3)
- [ ] 제품으로 수행할 수 있는 작업·서비스가 요약되어 있다 (§10②4)
- [ ] 유지보수 제공 여부와 내용이 있다 (§10②5)
- [ ] 문서 자체의 **식별자**(문서번호·개정번호·작성일)가 있다 (§10②6)
- [ ] 제품의 용도가 한 문단으로 명확하다 (§10②7)
- [ ] 적용한 표준·권고안이 있으면 기재했다 (§10②8)
- [ ] 실행 가능한 기능의 개요가 **기능 목록표**로 정리되어 있다 (§10③1)
- [ ] 입력값 범위·최대 레코드 수 등 **사용자가 접할 제약사항**이 수치로 적혀 있다 (§10③2)
- [ ] 비인가자 접근 방지 기능(로그인·권한)이 있다면 설명되어 있다 (§10③3)
- [ ] 컴포넌트 옵션·버전이 있으면 설명되어 있다 (§10③4)
- [ ] 성능 관련 시스템 구성·자원 조건과 **용량 정보**가 있다 (§10④)
- [ ] 특정 SW/HW에 의존적이면 그 정보가 있다 (§10⑤)
- [ ] UI 유형(웹/앱/CLI, 메뉴 기반 등)이 적혀 있다 (§10⑥1)
- [ ] 사용에 필요한 사전 지식(기술 영역·OS 지식)이 적혀 있다 (§10⑥2)
- [ ] 오류 방지 기능이 있으면 설명되어 있다 (§10⑥3)
- [ ] 저작권 보호 장치가 있으면 설명되어 있다 (§10⑥4)
- [ ] 지원 언어(한글 외)가 적혀 있다 (§10⑥5)
- [ ] 장애 시 운영 방법(에러 발생 시 대응)이 있다 (§10⑦1)
- [ ] 데이터 저장·복구 기능이 있으면 **절차**까지 적혀 있다 (§10⑦2)
- [ ] 암호화·사용자 인증 방식이 설명되어 있다 (§10⑧)
- [ ] 유지보수 지원 기능·변경 절차가 있다 (§10⑨)
- [ ] 설치 절차와 구성(구성도 포함)이 있다 (§10⑩)

## 2. 사용자취급설명서 (고시 §11)

- [ ] 목차가 있고, 분량이 많으면 **색인**도 있다 (§11⑤1)
- [ ] 문서 식별자(문서번호·버전·작성일)가 있다 (§11①6)
- [ ] 제품명·버전·공급자 정보가 제품설명서와 **같은 문자열**이다 (§11①7, §11③)
- [ ] 사용자가 호출 가능한 **모든 기능**에 설명과 사용 방법이 있다 (§11①2)
- [ ] 기능 목록이 제품설명서의 기능 목록과 1:1로 대응한다 (§11③)
- [ ] 설치에 필요한 **최소 저장 공간**이 적혀 있다 (§11①3)
- [ ] 관리 기능(사용자·권한·설정·로그) 실행에 필요한 정보가 있다 (§11①4)
- [ ] 문서가 여러 권이면 구성 정보(권별 역할)가 있다 (§11①5)
- [ ] **필수 데이터의 백업 및 복구 안내**가 있다 (§11①8)
- [ ] 모든 절차가 화면 순서와 일치한다 — 캡처의 메뉴명·버튼명이 실제와 같다 (§11②)
- [ ] 일반적이지 않은 용어·약어를 정의한 표가 있다 (§11⑤3)
- [ ] 전자문서로 제공 시 인쇄본 제공 가능 여부·획득 방법이 적혀 있다 (§11⑤2)
- [ ] 문장이 사용자 관점의 평서문이다 — 개발자용 내부 용어·코드명이 남아 있지 않다 (§11④)
- [ ] 문서에 없는 기능이 제품 화면에 없다 (범위 밖 기능은 숨김 처리 완료)

## 3. 실행 소프트웨어 — 품질 특성별 (고시 §12)

### 기능적합성 (§12①)
- [ ] 문서에 기술된 기능이 **전부** 구현되어 있다 (기능 목록표와 화면을 1:1 대조)
- [ ] 각 기능이 정확히 동작한다 (정상·경계·오류 입력 각 1건 이상 확인)
- [ ] 업무 목적 달성에 필요한 기능이 빠지지 않았다
- [ ] 문서에 없는 기능이 노출되지 않는다 (숨김·권한 처리 확인)

### 성능효율성 (§12②)
- [ ] 응답시간·처리율 **목표치**가 문서에 숫자로 있다
- [ ] 목표치를 측정할 수 있는 조건(데이터 건수·동시 사용자)이 정의되어 있다
- [ ] 대용량·다건 처리 시 동작이 정의되어 있다 (페이징·비동기·제한)
- [ ] CPU·메모리 사용이 시험 중 확인 가능하다(모니터링 화면 또는 로그)

### 호환성 (§12③)
- [ ] 시험 대상 OS·브라우저·DB·미들웨어 조합이 **환경표와 동일**하다
- [ ] 타 소프트웨어와 자원을 공유할 때 유해 영향이 없다(포트 충돌·라이브러리 충돌)
- [ ] 연동 시 데이터가 포맷·절차대로 누락 없이 교환된다(연계 시험 1회 이상)
- [ ] 연계 대상이 시험 시 모의(Stub)로 대체되면 그 사실이 문서에 있다

### 사용성 (§12④)
- [ ] 첫 화면에서 제품 목적·사용 시나리오를 알 수 있다 (데모·안내·샘플 데이터)
- [ ] 각 기능 설명이 매뉴얼에 빠짐없이 있다
- [ ] 오류 메시지가 **사용자가 무엇을 해야 하는지** 알려 준다 (코드·예외명 노출 금지)
- [ ] 입력 필드에 기본값·형식 안내가 있다
- [ ] 잘못된 입력에 대해 확인 요청 또는 올바른 값 예시를 제시한다
- [ ] 삭제·취소 같은 위험 동작에 확인 절차가 있다
- [ ] 다국어 지원 시 메뉴명·메시지가 지정 언어로 나온다 (미번역 문자열 없음)

### 신뢰성 (§12⑤)
- [ ] 장애 발생 시에도 운영 가능한 방법(재시작·대체 경로)이 있다
- [ ] **백업**과 **복구**가 모두 있고, 복구 절차가 문서화되어 있다
- [ ] 복구를 실제로 1회 수행해 봤다 (문서만 있고 안 해 본 절차는 시험에서 드러난다)
- [ ] 로그·세션 만료·동시 접속 등 운영 중 상황이 정의되어 있다

### 보안성 (§12⑥)
- [ ] 인증되지 않은 사용자의 데이터 접근이 차단된다 (URL 직접 입력·API 직접 호출 포함)
- [ ] 권한별로 보이는 데이터·메뉴가 실제로 다르다 (관리자/일반/조회자 3개 계정으로 확인)
- [ ] 비밀번호·주민번호 등 중요 정보가 암호화되어 저장된다
- [ ] 통신 구간 암호화(HTTPS)가 적용되고, 종료 지점이 문서와 같다
- [ ] 접근 이력·감사 로그가 기록되고 보관 기간이 정해져 있다
- [ ] 세션 타임아웃·로그아웃이 동작한다
- [ ] 시험용 계정의 비밀번호가 문서에 평문으로 남지 않도록 전달 방식을 정했다

### 유지보수성 (§12⑦)
- [ ] 오류 원인을 찾을 수 있는 로그·진단 기능이 있다 (로그 레벨·위치 문서화)
- [ ] 설정 변경이 코드 수정 없이 가능하다 (설정 파일·관리 화면)
- [ ] 자체 점검(헬스체크·테스트) 기능이 있으면 독립적으로 실행된다
- [ ] 관리자 화면에서 로그를 조회할 수 있다면 그 경로가 매뉴얼에 있다

### 이식성 (§12⑧)
- [ ] 제시한 환경에서 설치가 매뉴얼만 보고 가능하다 (평가자가 직접 수행)
- [ ] 설치 절차서에 사전 준비물(계정·권한·패키지)이 있다
- [ ] 최소 사양과 권장 사양이 수치로 있다
- [ ] 데이터 이관(대체 설치)이 필요한 경우 절차와 검증 방법이 있다

## 4. 시험환경 · 구성도

- [ ] 설치 구성도가 있고, IP·포트·버전이 그림 안에 있다
- [ ] 구성도 = 환경표 = 실제 접속정보가 **같은 문자열**이다
- [ ] OS·미들웨어·DB·브라우저 버전이 **화면 캡처와 일치**한다
- [ ] 접속 URL·계정·권한이 정리된 표가 있다 (시험 기간 유효)
- [ ] 외부 연계는 실서비스/모의(Stub) 구분이 표시되어 있다
- [ ] 방화벽·포트 개방 목록이 있다 (단방향/양방향 구분)
- [ ] 시험용 데이터가 준비되어 있다 (개인정보는 가상 데이터로)
- [ ] 데이터 초기화 방법이 있다 (시험 반복 시 이전 데이터가 결과에 영향 주지 않게)
- [ ] 원격 접속 수단(화상·원격데스크톱)이 준비되어 있다 — 현장 방문/원격 여부 사전 협의
- [ ] 구성 변경(패치·버전업)이 있었다면 **최신본으로 재설치**했고 캡처도 갱신했다
- [ ] 시험 중 사용할 계정의 잠금·만료 정책을 확인했다 (시험 도중 잠기면 일정이 밀린다)

## 5. 일정 · 보완 대응

- [ ] 접수 → 사전점검 → 평가자 배정 → 평가(약 3~5주) → 심의 → 발급 흐름을 역산한 일정표가 있다
- [ ] 보완 요청은 **3회까지** 가능하고 추가 비용이 발생할 수 있음을 인지했다 (§14④)
- [ ] 결함 보고서를 받으면 수정→재시험 범위를 정리하는 담당자가 정해져 있다
- [ ] 문서 수정 시 **개정 이력**을 남긴다 (어느 판본으로 재시험했는지 추적)
- [ ] 인증 후 변경(기능·UI·암호·환경) 시 재인증 필요 여부를 판단할 기준을 문서로 정리해 두었다

## 단골 결함 5선 (Before / After)

아래는 특정 업체·제품 사례가 아니라, 여러 시험에서 **반복적으로 나타나는 패턴**을 일반화한 예시입니다. 등장하는 이름·버전·수치는 모두 가상의 값입니다.

### 1. 환경표와 화면 캡처의 버전 불일치

**증상** — 제출 문서의 환경표에는 `Windows 10 / Chrome 118`, 붙인 캡처의 창에는 `Windows 11 / Chrome 120`. 기능은 정상인데 "문서대로 재현되지 않는다"는 지적을 받습니다.

**왜 걸리는가** — 이식성(§12⑧1)과 문서 정확성(§11②). 평가자는 문서에 적힌 환경을 기준으로 시험 절차를 세우므로, 캡처와 환경이 다르면 시험 절차 자체를 신뢰할 수 없습니다.

**Before**
```
[시험환경]
- OS: Windows 10
- Browser: Chrome 최신
(그림: Windows 11 캡처)
```

**After**
```
[시험환경]
- 평가용 PC: Windows 11 23H2 (빌드 22631.2861)
- 브라우저: Chrome 120.0.6099.130
- 서버: Windows Server 2022 / Tomcat 10.1 / OpenJDK 17.0.9
※ 모든 캡처는 위 환경에서 2026-11-18에 재촬영 (문서 개정 3판)
```

**재발 방지** — 캡처는 **마지막에** 찍습니다. 문서를 먼저 확정하고, 확정된 환경에서 화면을 다시 캡처하면 불일치가 원천적으로 사라집니다. 캡처 파일명에 촬영일을 넣어 두면 추적이 쉽습니다.

---

### 2. 문서끼리 제약사항이 모순

**증상** — 제품설명서에는 "첨부파일 최대 10MB", 사용자취급설명서에는 "20MB", 실제 화면 안내 문구는 "5MB". 기능은 되지만 세 곳이 서로 다릅니다.

**왜 걸리는가** — 일관성(§10①, §11③)과 사용성(§12④). 문서 간 불일치는 "문서를 신뢰할 수 없다"는 판단으로 이어지고, 그 문서로 시험한 결과 전체의 신뢰도에 영향을 줍니다.

**Before**
```
제품설명서: 첨부파일은 최대 10MB까지 업로드할 수 있다.
매뉴얼: 파일 첨부는 20MB까지 지원합니다.
화면: (안내) 5MB 이하 파일만 첨부하세요.
```

**After**
```
[공통 제약사항 표 — 문서 3종이 이 표를 그대로 인용]
| 항목 | 값 | 비고 |
| 첨부파일 1건 | 10MB | 초과 시 오류 메시지 E-1004 |
| 첨부파일 합계 | 50MB | |
| 동시 접속 | 100 세션 | 성능 목표와 동일 조건 |
```
그리고 화면 안내 문구도 `10MB`로 수정하고, 상수를 설정 파일에서 읽어 오도록 바꿉니다.

**재발 방지** — 제약사항은 **한 표에서만** 관리하고 나머지 문서는 그 표를 참조합니다. 화면 문구도 같은 설정값을 쓰게 하면 코드·문서·UI가 함께 움직입니다.

---

### 3. 백업은 있는데 복구 절차가 없다

**증상** — "매일 02:00 DB 백업"은 문서에 있는데, 복구 방법·소요 시간·검증 절차가 없습니다. 평가 중 "복구해 보라"는 요청에 답하지 못합니다.

**왜 걸리는가** — 신뢰성(§12⑤3)은 백업뿐 아니라 **복구 가능성**을 봅니다. 제품설명서에도 데이터 저장·복구 기능이 있으면 절차를 기술해야 합니다(§10⑦2). 백업만 있고 복구가 없으면 "기능이 문서에만 존재"하는 상태입니다.

**Before**
```
- 백업: 매일 02:00 자동 백업 (DB, 첨부파일)
```

**After**
```
[백업]
- 대상: DB 전체, 첨부파일 저장소
- 주기: 매일 02:00 전체 / 4시간마다 증분
- 보관: 30일, 별도 서버(10.10.5.10) 및 외부 저장소 1copy

[복구]
1. 서비스 중지 → 2. 최신 전체 백업 선택 → 3. DB 복원(예상 25분, 100GB 기준)
4. 증분 반영 → 5. 첨부파일 동기화 → 6. 정합성 점검 쿼리 실행 → 7. 서비스 재개
- 최근 복구 훈련: 2026-11-10, 소요 32분, 결과 정상 (기록: 운영로그 3-2)
```

**재발 방지** — 복구 절차는 **한 번 실제로 해 보고** 소요 시간을 적습니다. 문서만으로 만든 절차는 시험에서 거의 예외 없이 막힙니다.

---

### 4. 인증 범위 밖 기능이 화면에 그대로 보인다

**증상** — 인증 범위는 "업무 포털"인데, 관리자 메뉴에 "실험적 기능(베타)"이 남아 있습니다. 문서에 설명이 없으니 "문서에 없는 기능이 구현되어 있다"는 지적이 됩니다.

**왜 걸리는가** — 기능적합성(§12①)과 문서 일치. 인증 범위에 포함되지 않는 기능은 제품에서 **삭제되거나 접근 불가**해야 합니다. 평가 착수 후 기능을 추가·변경하면 시험 범위가 다시 흔들립니다.

**Before**
```
(관리자 로그인 → 좌측 메뉴)
- 대시보드
- 사용자 관리
- 실험 기능 (BETA)   ← 문서에 없음
- 시스템 설정
```

**After**
```
방법 A — 배포에서 제외: 인증 빌드에서 베타 모듈을 빌드 대상에서 제외
방법 B — 권한으로 차단: 기능 플래그 off, 메뉴 미노출, 직접 URL 접근 시 403
+ 제품설명서에 "인증 범위: 대시보드·사용자 관리·시스템 설정"을 명시
+ 평가 착수 후 기능 추가·변경 금지 원칙을 내부 공지
```

**재발 방지** — 접수 시점에 **인증 빌드(배포본)** 를 고정하고, 그 빌드의 커밋 해시·빌드 번호를 문서에 적습니다. 시험 중 새 기능이 섞여 들어가는 사고를 막습니다.

---

### 5. 오류 메시지가 내부 코드·예외명을 그대로 노출

**증상** — 잘못된 입력에 `NullPointerException at com.example.service.UserService.save(UserService.java:142)` 같은 문구가 뜹니다. 기능은 막혔지만 사용자는 무엇을 고쳐야 할지 알 수 없습니다.

**왜 걸리는가** — 사용성(§12④2, §12④4)과 보안성(내부 구조 노출). 메시지는 "올바른 결과와 지시사항"을 전달해야 하고, 입력 오류에는 올바른 값 예시를 제시해야 합니다.

**Before**
```
저장 실패: ERR_5001 (SQLException: duplicate key value violates unique constraint "uq_user_email")
```

**After**
```
이미 가입된 이메일입니다.
- 다른 이메일을 입력하거나, 기존 계정으로 로그인해 주세요.
[로그인] [다시 입력]
(내부 로그에는 ERR_5001 + 상세 스택 기록, 사용자 화면에는 미노출)
```

**재발 방지** — 오류 메시지 **표준표**(코드·사용자 문구·조치 안내·로그 레벨)를 만들고, 화면에는 사용자 문구만, 상세는 로그로 보냅니다. 예외 메시지를 그대로 화면에 뿌리는 코드 경로를 검색해 차단합니다.
